# Staging Auth0 verified-login PostgreSQL permission correction — Nov 5 2026

**Only repo:** `alisufyan-ai7/trading-signal-intelligence`; PR #93 draft, not production. Real owner staging signup with delivered `Verify your email` (Resend) subsequently received verification link. On fresh human login, Railway staging `GET /auth/callback` at **2026-11-05 19:19 UTC** returned **HTTP 500**. Sanitized ASGI traceback, with callback URL/token values excluded, conclusively identified `psycopg.errors.InsufficientPrivilege: permission denied for table vowsig_accounts` at `PostgresAccountStore.complete_verified_login()` while selecting an existing verified account.

**Cause:** `SELECT ... FOR UPDATE OF a` on `vowsig_accounts a` attempted an exclusive row lock under the deliberately restricted `vowsig_app` role. SQL migration 007 grants `SELECT` and column-scoped `INSERT` to the runtime, **not UPDATE** on `vowsig_accounts`; that prohibition prevents owner/role or email changes. Earlier staging app read-only role acceptance checked privileges but did not exercise full initial/returning verified session creation. Earlier disposable integration tests used PostgreSQL administrative credentials rather than the role.

**Narrow safe solution:** In `store.py`, under the existing per-login database transaction, acquire `pg_advisory_xact_lock()` on a signed 64-bit SHA256-derived key from the bounded, immutable OIDC issuer and subject, then run the existing account identity/entitlement `SELECT` **without `FOR UPDATE OF a`**. This preserves serialized returning and initial signins for the same issuer+subject, prevents concurrent session issuance races while revoking prior sessions, and requires no account UPDATE privilege or migration. Hash collisions can only cause extra serialization, not identity mixing. Preserve all user/email uniqueness constraints and account/research/MFA denials.

**New real disposable PG18 CI acceptance** in `scripts/vowsig_accounts_ci_pg18_role_boundaries.py`: create a throwaway DB and restricted `vowsig_app` session with `SET SESSION AUTHORIZATION`; call actual `PostgresAccountStore.complete_verified_login()` for existing bound identity, new identity, and two concurrent returning logins; prove one unrevoked session, member role, and `vowsig_accounts UPDATE` remains denied. Uses exact disposable loopback admin DSN guarded by GitHub CI identity, no Railway SQL or secrets. Do not rerun staging migrations.

**Release gate:** exact-head CI success, then owner-authorized **staging-app-only** pinned SHA deployment and real human fresh `/auth/start`/verified callback trial. **No production Railway, GitHub main, Resend provider settings, Auth0 user/secret changes or broker activity** approved.
