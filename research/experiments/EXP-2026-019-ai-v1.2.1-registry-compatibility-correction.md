# EXP-2026-019 — AI-v1.2.1 registry compatibility correction

_Status: OFFLINE CANDIDATE / NOT PUBLISHED / 2026-10-09 UTC_

## Problem

The AI-v1.2.1 activation anchor froze the SHA-256 of the entire shared
`config/instruments.json` registry.

AI-v1.3 K2 subsequently added exactly two Binance Spot mappings:

- `ETH/USDT -> ETHUSDT`;
- `SOL/USDT -> SOLUSDT`.

The resulting whole-file hash changed from:

`b92b80d18f422ba012b991ca8ba5a538f9212ee2823813d29754f24a804491ca`

to:

`f2f3d993fdd171ac43edd5234e18cfbea3eb7cf8da5dc2e6e6d4529613cd1681`.

Read-only VPS evidence showed:

- all AI-v1.2.1 ledgers valid;
- all activation records still match the immutable anchor;
- public exposure disabled;
- broker execution disabled;
- `instrument_registry` is the only frozen artifact mismatch;
- the expansion scheduler is fail-closed with last result 1.

## Correction principle

Do **not** modify or rewrite the immutable AI-v1.2.1 activation anchor.

Do **not** modify any source/script that is already part of the AI-v1.2.1
activation artifact hash set.

Instead, add a versioned compatibility layer outside the frozen artifact set.

The compatibility layer may admit the registry mismatch only when all of these
hold:

1. the anchor expects the exact original registry SHA-256;
2. the checked-out registry has the exact K2-approved SHA-256;
3. the original registry can be recovered from the exact activation commit;
4. every pre-existing registry entry is semantically identical;
5. top-level schema/notes are identical;
6. the only new canonical entries are the exact ETH/USDT and SOL/USDT Binance
   Spot mappings;
7. every other AI-v1.2.1 frozen artifact still passes its original exact-hash
   check.

Any deletion, mutation, extra addition, wrong hash or different addition fails
closed.

## Runtime isolation

The original frozen:

- observability implementation;
- runtime verifier;
- live runner;
- task runner;

remain byte-identical to the activation anchor.

New corrected wrappers are prepared separately and are not installed by this
experiment.

The future corrected live runner changes only the runtime-verifier hook. It does
not change the AI decision contract, feature logic, provider configuration,
market set, guardrails, lifecycle logic, ledger implementation or broker/public
boundaries.

## K3 integration

The AI-v1.3 activation script and AI-v1.3 runtime verifier on this candidate
branch use the compatibility verifier for the existing AI-v1.2.1 parallel
runtime precondition.

This does not authorize K3 execution.

## Scheduler

No scheduled task is created, changed, enabled, disabled, started or stopped by
this correction package.

The existing AI-v1.2.1 task remains fail-closed until a separately authorized
publication and operational task-action update points it at the corrected
wrapper. After that update, recovery should occur only through a natural
scheduled run; no manual provider run is authorized merely to clear a task
result.
