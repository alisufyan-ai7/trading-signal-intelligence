- Windows account: SAME logged-on user already holding four Generic Credential entries. **Interactive logon token** supports leaving RDP connected or disconnected *without signing out*; an actual full Windows Sign out prevents this task running. No scheduled task password or plaintext cloud credentials are placed in the task command.
- Program: `C:\ProgramData\VowSig-S02-AutoBackup\current\scripts\run_vowsig_s02_automatic_backup_v0_1.ps1`, stable self-contained Python `.venv`, pinned SDK copied from already validated local B3/S3 testing environment, and isolated source `src/`. Fresh random object key and 256-bit AES data key, both AWS/B2 version-pinned readbacks, and TWO encrypted provider recovery receipts plus local encrypted receipt per run. The task additionally performs a **separate independent exact-version cloud manifest + both-provider SQLite restore**; only then writes PASS to local history.
- Credential Manager fifth Generic target: **`VowSig.S02.Recovery.Passphrase.v1`**; set **User name `VowSigS02`** and Password to an owner-controlled unique private 16–256 character recovery passphrase. Enter once with Windows Credential Manager GUI; masked command-line/RDP-console prompts are not used in the scheduler. This same passphrase can be the one used by the first manual backup, so only one recovery secret must be kept, but the user MUST save the phrase independently OFF VPS. Any newly chosen phrase applies to future scheduled backups only, not the older manual backup; the older recovery phrase remains necessary if different.
- 4 existing fixed credential targets remain `VowSig.S02.AWS.Writer.v1`, `VowSig.S02.AWS.Reader.v1`, `VowSig.S02.B2.Writer.v1`, `VowSig.S02.B2.Reader.v1`. They are not re-entered in PowerShell. Fifth passphrase in same Windows vault is the unavoidable tradeoff for noninteractive encryption/recovery; compromise of that Windows account can expose it. Separate off-VPS independent key custody is essential.

## Older backup files / retention

**KEEP ALL CLOUD BACKUPS. NEVER DELETE/OVERWRITE ANY OLD CLOUD VERSION AUTOMATICALLY IN V0.1.** Every scheduled run gets a unique `backup-<32 hex>` ID, writes new independent AES ciphertext to both buckets, retains the corresponding private encrypted manifest in both, and preserves encrypted local receipts. The first PASS backup ID `backup-8bce80179c524ace8f4a52cb702b3716` remains intact and recoverable with its original saved passphrase. No AWS/B2 lifecycle rule, S3/B2 DeleteObject, version purge, automatic pruning or IAM expansion is performed by this delivery.

Rationale: retaining multiple dated points-in-time enables recovery from discovered corruption or data poisoning. At daily cadence, cloud object counts and billable storage accumulate over time, especially if versioning retains noncurrent versions; **minimal cost intended, not guaranteed permanently zero**. A later owner-approved retention policy (e.g. 30 daily + 12 monthly recovery points) requires explicit safe provider version/delete rights, paired data+manifest pruning, independent verification of retained restore points and an audit; **not** part of first automatic rollout because an incorrect cleanup can destroy the only recoverable state. Monitor AWS and B2 storage/requests, review after enough history accumulates. Removing local encrypted receipt files does NOT remove cloud objects but makes offsite recovery more dependent on remote manifest access; do not manually delete without independent recovery confirmation.

## Failure handling and visibility

- `C:\ProgramData\VowSig-S02-AutoBackup\state\history.jsonl` — newline-delimited private sanitized UTC PASS/HOLD summaries with each new nonsensitive backup ID and verified record count. Task Scheduler Last Run Result must be 0; first scheduled attempt should report `FIRST_SCHEDULED_BACKUP=PASS`.
- On ambiguous AWS/B2 upload, manifest write, or cold restore failure: `operator-review-required.json` in the same state folder. The file contains ONLY nonsecret identifiers/status, optionally backup ID recovered from a sanitized provider outcome. **All later automatic runs skip network requests until the owner reconciles and manually clears the latch.** No automatic retry, deletion or overwrite.
- On missing fifth credential or source file: no provider requests, sanitized credential/source HOLD. Task registers only if initial readiness PASS. Owner should inspect scheduled task result and history after RDP disconnect and especially after Windows reboot/logoff; this installer does NOT configure out-of-band email/Telegram push notifications. A logged failure is not equivalent to a notification delivered to the owner.
- A single immediate task-backed invocation is started during installation to check real scheduler credential access, provider calls, encrypted receipts and independent cold recovery. If it times out at installer observation window, task remains running; DO NOT launch a second copy while the first may be active. Check Task Scheduler and state file. The installer preserves existing production tasks and refuses to overwrite an existing task/runtime.

Owner-run installation script must use a SHA-pinned clean disposable GitHub checkout from this PR, verify source/runbook/head and production clean before executing `scripts/install_vowsig_s02_automatic_backup_v0_1.ps1` with exact `-Candidate`, `-ExpectedHead`, `-Live` parameters. The installer **creates a new isolated ProgramData runtime, verifies stable Python package imports and four-role + fifth passphrase Windows vault readiness, and adds ONE new Windows Task Scheduler task**. It does not merge PRs or modify other scheduled tasks. It then launches one initial scheduled attempt and checks its local audit.
3. Acceptance: `AUTOMATIC_BACKUP_INSTALL=PASS`, `SCHEDULED_CREDENTIALS=READY`, `RELOCATED_STABLE_RUNTIME=PASS`, `FIRST_SCHEDULED_BACKUP=PASS`, fresh unique backup ID (different from manual ID), `LastTaskResult=0`, cloud restore PASS from exact client code. 4. After reboot or daily window, inspect `Get-ScheduledTaskInfo -TaskName "VowSig S02 Encrypted Dual Cloud Backup"`, the last history entry, and absence of `operator-review-required.json`.
