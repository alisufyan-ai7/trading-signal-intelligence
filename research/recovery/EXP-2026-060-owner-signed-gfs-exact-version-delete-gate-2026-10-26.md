## Implemented modules (stacked small draft onto PR #87)

- `s02_gfs_owner_signed_prune_plan_v0_1.py`: validates the full exact GFS `choose_gfs` plan SHA, protected IDs and absence of unrelated HOLDs. Freezes **ONE expired backup ID** and its exact **4 version references** (AWS encrypted data+manifest; B2 encrypted data+manifest) into an AES-256-GCM/scrypt sealed *private* capsule with a unique random salt+nonce and public ciphertext SHA-256. Exact opaque provider VersionIds are never logged or committed. Plan states `prepared_utc`, **7 full days not-before** and 14-day expiration. The owner must independently sign the context/domain-separated SHA-256 of the *sealed* capsule using an **Ed25519 private key stored securely OFF VPS**. Only the separately pinned Ed25519 **public** key may be used on the VPS; the approval key is not an AWS/B2 key, not the recovery passphrase, and not available to the daily backup task. Verifier checks signature, grace, plan age, protected set, fresh GFS, and exact 4 unchanged cloud version IDs. A new signed plan is required if a version changes or approval expires.
- `s02_gfs_exact_inventory_for_pruning_v0_1.py`: uses existing already-proven reader-only AWS/B2 `list_object_versions` machinery for **complete four-prefix inventories**. Unknown objects, missing cloud manifest/data counterparts, multiple versions or delete markers, invalid data VersionId (`null`), cross-provider mismatch or absent listing rights HOLD. This is read-only with no import-time provider requests.
- `s02_gfs_single_version_delete_executor_v0_1.py`: a **separate** four-operation exact-`VersionId` deletion executor, originally disabled by the immutable source gate `PRODUCTION_CLOUD_DELETE_ENABLED = False`. It refuses *before any cloud request* while gate remains false; there is no user-facing CLI, Windows task, configuration/env override, provider delete credentials, or live installation. A future manually approved release must explicitly alter this gate in reviewed source rather than accepting a CLI flag or secret. Release would first recheck all backups/GFS/versions, cold restore **EVERY retained point independently from AWS and B2**, verify independent reader vs deletion identities, create owner-only fsynced/exclusive journal, then delete exactly one ID in order **AWS manifest → AWS data → B2 manifest → B2 data** using four SDK `delete_object(Bucket=...,Key=...,VersionId=...)` requests, with no retries. Each attempt has a write-ahead durable journal event. A failure/ambiguous response leaves a HOLD journal and persistent global lock, prohibiting retries and further automatic prunes until a separately authorized manual reconciliation. Even a successfully completed candidate cannot be resealed with a new salt/nonce and deleted again because its one-shot journal is keyed by **backup ID**, not ciphertext SHA. After 4 responses, the executor re-lists both providers expecting exactly all remaining IDs and repeats all retained AWS+B2 cold restores; only then writes completed journal. It **never** deletes local encrypted contingency receipts, the active S02 database, an owner pin, an existing production scheduler, unrelated keys or cloud versions.
- `tests/test_s02_gfs_owner_signed_single_delete_v0_1.py`: **19 synthetic/offline** tests for GFS eligibility, manual/recent pin protections, AES capsule secrecy, domain-separated signature, 7-day minimum and 14-day expiry, changed cloud versions, B2 manifest integrity, invalid/null VersionIds, complete listing, provider incident/unknown entry, duplicate sealed nonce planning, durable no-retry on failure, explicit `VersionId` on all four simulated deletes, pre/post restore and distinct credentials. Synthetic clients do **not** call AWS, B2, or delete real objects.
- `.github/workflows/s02-gfs-pruning-offline-tests.yml`: restricted `contents:read`, no secrets, no real provider endpoints, Python 3.12 synthetic-only PR checks. Source defaults closed.
- `EXP-2026-060-proposed-separate-aws-retention-delete-only-policy.json`: **not installed**.
