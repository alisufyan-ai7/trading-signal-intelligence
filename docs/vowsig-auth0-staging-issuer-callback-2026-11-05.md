# Staging Auth0 RFC 9207 authorization-response issuer compatibility (2026-11-05)

**Actual staging HTTP evidence:** Owner's browser showed `{"detail":"Sign-in response rejected"}` after Auth0 redirect to `/auth/callback`. Railway staging runtime HTTP log `2026-11-05T19:01:38Z` showed HTTP 400 with callback parameter **NAMES ONLY** `code`, `state`, `iss`. Do not print, commit or repeat their values, which include short-lived secrets. The exact preexisting `auth_api.py` allowlist `{"code","state","session_state"}` rejected the RFC 9207 `iss` field before any code token exchange.

**Narrow correction:** Accept optional `iss` only if there is *at most one* and the value matches the server-side statically configured Auth0 issuer **byte-for-byte** (including its trailing slash). Reject different/missing slash/empty, repeated `iss`, duplicated `session_state`, provider `error`, unknown parameters and existing bad/repeated `code`/`state` exactly as before. Validate before consuming DB-backed state; existing OIDC verified ID-token signature, issuer, audience, nonce, PKCE, email_verified checks, session rotation and CSRF remain enforced. Existing providers not emitting `iss` remain supported. All new regression cases run through FastAPI TestClient with simulated signed trust boundaries, not real Auth0.

**Staging deployment only:** After exact-SHA CI succeeds, update only Railway project `vowsig-staging-20261105` staging app to that tested SHA, leave production Railway project, public VowSig flags, PostgreSQL grants, scheduled Windows tasks, Resend provider and main branch unchanged. Then owner repeats **fresh** `/auth/start` (never refresh previous callback code) in the same browser, with an email-verification-controlled *test* identity and observes whether returned callback reaches `/app/`. Successful callback is not proof of actual Resend delivery unless Resend metadata for the specific verification message is available. No real signup/email has been confirmed yet.

The independent staging PostgreSQL TLS, restricted app SQL and Auth0 public OIDC endpoints already passed in earlier PR #93 checkpoints. Production release and owner MFA/rollback remain separately approved gates.
